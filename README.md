# Connect Four (4 в ряд) на Python

Навчальний проєкт з гри «Чотири в ряд» (Connect Four) з графічним інтерфейсом на PySide6 та штучним інтелектом Minimax.

## 1. Правила гри
Гра проходить на полі 7 колонок на 6 рядків. Два гравці по черзі кидають фішки у стовпчики. Через гравітацію фішка падає на найнижчу вільну клітинку в обраній колонці.
Перемагає гравець, який першим вибудує лінію з 4 своїх фішок:
- по горизонталі;
- по вертикалі;
- по діагоналі вгору-вправо або вниз-вправо.
Якщо всі 42 клітинки заповнені, а лінію з 4 фішок ніхто не зібрав, фіксується нічия.

## 2. Архітектура та структура проєкту
Проєкт побудований за модульним принципом з чітким розділенням відповідальності:

```
4InARow/
├── main.py - точка входу, запуск QApplication
├── requirements.txt - залежності (PySide6)
├── README.md - документація проєкту
│
├── game/ - ядро гри (чистий Python без UI та AI)
│   ├── board.py - стан сітки 7х6, падіння фішок, перевірка перемоги та нічиєї
│   └── game.py - керування партією, черговість ходів, статус матчу
│
├── ai/ - штучний інтелект
│   ├── minimax.py - алгоритм пошуку Minimax з Alpha-Beta відсіканням
│   └── evaluation.py - евристична функція оцінки позицій на дошці
│
└── ui/ - інтерфейс користувача (PySide6)
    ├── game_board.py - віджет малювання дошки та фішок (QPainter)
    └── main_window.py - головне вікно, панель налаштувань, статистика, фоновий потік
```

### Як взаємодіють модулі:
- UI звертається до Game і Minimax.
- Minimax працює тільки з об'єктом Board і викликає Evaluation.
- Game працює тільки з Board.
- Game та Board нічого не знають про графічний інтерфейс або штучний інтелект. Це дозволяє легко перевіряти логіку гри незалежно від інтерфейсу.

## 3. Штучний інтелект (Minimax та Alpha-Beta)

### Алгоритм Minimax
Connect Four - це гра для двох гравців з нульовою сумою, де виграш одного означає програш іншого. Комп'ютер будує дерево можливих ходів на кілька кроків уперед:
- На кроці AI (максимізація) алгоритм шукає хід з найбільшою вигодою для себе.
- На кроці суперника (мінімізація) алгоритм припускає, що опонент зіграє найсильнішим для себе і найгіршим для AI чином.

### Alpha-Beta відсікання
Якщо перебирати всі можливі ходи підряд, кількість варіантів зростає лавиноподібно (на глибині 6 це більше 100 000 позицій). 
Alpha-Beta відсікання зберігає дві межі:
- alpha: найкраща гарантована оцінка для AI;
- beta: найкраща гарантована оцінка для суперника.
Коли виявляється, що в поточній гілці результат гірший, ніж вже знайдений раніше (alpha >= beta), алгоритм одразу зупиняє розгляд цієї гілки і повертається назад. Кінцевий вибір ходу від цього не змінюється, але перевіряється в рази менше позицій.

### Оптимізація порядку ходів (Move Ordering)
Колонки перевіряються не зліва направо (0, 1, 2, ...), а від центру до країв: [3, 2, 4, 1, 5, 0, 6]. 
У грі 4 в ряд центральний стовпчик найвигідніший, бо через нього проходить найбільше переможних діагоналей і горизонталей. Знаходячи сильні ходи першими, алгоритм відсікає більшість бічних гілок на самому початку.

### Оптимізація пам'яті (undo_move)
Замість того, щоб копіювати всю дошку на кожному кроці рекурсії, алгоритм робить хід (drop_piece), викликає наступний крок, а після повернення просто очищає клітинку (undo_move). Це економить пам'ять і прискорює пошук.

## 4. Евристична оцінка позиції (ai/evaluation.py)
Прорахувати всю партію до кінця неможливо, тому пошук зупиняється на заданій глибині. Для оцінки дошки використовується функція evaluate_board:
Вона розбиває поле на відрізки по 4 клітинки у 4 напрямках (горизонталь, вертикаль, обидві діагоналі) через векторні зміщення:
- 4 свої фішки в ряд: перемога (+100000 балів);
- 3 свої фішки + 1 порожня: +100 балів (небезпечна лінія);
- 2 свої фішки + 2 порожні: +10 балів (перспективна зв'язка);
- 3 фішки суперника + 1 порожня: -120 балів (пріоритет термінового блокування загрози);
- 2 фішки суперника + 2 порожні: -10 балів;
- контроль центральної колонки: +3 бали за кожну свою фішку в центрі (мінус 3 за фішки суперника).

## 5. Графічний інтерфейс та асинхронність

### Віджет поля (ui/game_board.py)
Поле намальовано через QPainter розміром 490 на 420 пікселів:
- кожна клітинка має розмір 70х70 пікселів з отвором діаметром 50 пікселів;
- червоні фішки - Гравець 1, жовті фішки - Гравець 2, світло-сірі - порожні місця;
- при перемозі виграшна лінія з 4 фішок виділяється зеленим контуром;
- хід робиться простим кліком мишкою по потрібній колонці.

### Асинхронний потік (QThread)
Щоб вікно програми не зависало під час розрахунків AI (особливо на глибині 6-8), обчислення виносяться в окремий робочий потік AIWorker на базі QThread. Інтерфейс у цей час показує напис "AI думає...", а після розрахунку оновлює поле без підвисань.

### Режими гри
1. Human vs AI: людина (червоні) проти комп'ютера (жовті).
2. Human vs Human: двоє людей грають по черзі на одному комп'ютері.
3. AI vs AI: демонстраційна гра двох ботів з можливістю виставити кожному свою глибину.

### Налаштування складності
Глибина пошуку для AI налаштовується від 1 до 8:
- 1-2: легкий рівень, AI бачить тільки хід прямо перед собою, реагує миттєво;
- 3-4: середній рівень, впевнено грає і блокує прості загрози;
- 5-6: складний рівень (рекомендований), бачить комбінації на кілька ходів уперед, час ходу 0.1-0.4 с;
- 7-8: експертний рівень, глибокий прорахунок варіантів.

### Статистика
Після кожного ходу комп'ютера на панелі виводиться:
- назва алгоритму (Minimax);
- глибина пошуку;
- кількість проаналізованих позицій;
- час прийняття рішення в секундах;
- обрана колонка;
- числова оцінка позиції;
- загальний лічильник ходів і середній час AI за партію.

## 6. Встановлення та запуск

Вимоги: Python 3.11 або новіший.

1. Відкрити термінал у папці з проєктом:
cd "шлях_до_папки"

2. Створити та активувати віртуальне середовище (рекомендовано):
python -m venv .venv
.\.venv\Scripts\Activate.ps1

3. Встановити бібліотеки:
pip install -r requirements.txt

4. Запустити гру:
python main.py
